# 추가 Python 코드 리뷰 메모

검토 대상:

- `style_config_loader.py`
- `excel_report_generator_with_style.py`
- `hwpx_report_writer_revised4★ - (1).py`

## 총평

세 파일은 모두 현재 보고서 자동화 프로젝트에 직접 도움이 되는 코드입니다. 특히 엑셀/HWPX 표를 `TableData`, `TableRow` 같은 중간 구조로 정규화한 뒤 문장을 생성하는 흐름은, 지금 VBA add-in 안에 모든 로직을 넣는 것보다 유지보수성이 좋습니다.

다만 그대로 기존 add-in에 섞어 넣기보다는 별도 Python 엔진으로 분리하는 편이 안전합니다. 기존 매크로와 충돌 가능성을 낮추고, 향후 외부 EXE 런처에서 선택적으로 호출할 수 있기 때문입니다.

## 좋은 점

- 문체 설정을 JSON으로 분리하려는 방향이 좋습니다.
- 표 추출 → 전체 요약 → 지역/특성 비교 → 문장 렌더링으로 단계가 나뉘어 있습니다.
- HWPX 내부 XML을 직접 읽는 코드가 있어, 한글 API 없이도 기존 보고서 구조 분석이 가능합니다.
- 조사 보고서에서 중요한 `긍정/만족/인지`, `평균`, `100점 환산`, 배너별 비교 문장 생성의 뼈대가 이미 있습니다.

## 수정해서 편입한 부분

- `report_automation_engine/` 폴더를 새로 만들고, 세 파일을 프로젝트용 이름으로 편입했습니다.
- 기본 스타일 설정 파일 `config/default_style_schema.json`을 추가했습니다.
- GUI에서 스타일 JSON 선택을 취소하면 기본 설정을 사용하도록 했습니다.
- `choose_rank_columns()`가 전역 설정 `GLOBAL_CONFIG`에 의존하던 부분을 명시적 설정 인자로 바꿨습니다.
- 대형 엑셀 파일에서 불필요하게 모든 시트의 병합셀을 먼저 해제하지 않도록, 빠른 표 시작 행 후보 탐색 함수를 추가했습니다.
- 각 모듈과 주요 데이터 구조에 코드리뷰용 주석을 보강했습니다.

## 남은 리스크

- `excel_report_generator.py`는 openpyxl 기반이라 대형 집계표에서는 여전히 느릴 수 있습니다.
  - KISDI 샘플 전체 스캔은 현재 120초 제한 안에 완료되지 않았습니다.
  - 다음 개선은 `read_only=True` 기반 1차 스캔과, 필요한 표 블록만 일반 모드로 다시 읽는 2단계 구조가 좋습니다.
- 엑셀 생성기 안에 스타일 로더 코드가 중복되어 있습니다.
  - 지금은 원본 흐름 보존을 우선했지만, 다음 정리 단계에서는 `style_config_loader.py` 하나로 통합하는 편이 좋습니다.
- HWPX 모듈은 파일명은 writer지만 실제로는 “기존 HWPX 표 분석 및 TXT 초안 생성”에 가깝습니다.
  - HWPX에 직접 문단/표를 삽입하는 기능은 아직 별도 구현이 필요합니다.
- GUI는 tkinter 기반이라 외부 EXE 런처와 통합할 때는 GUI 호출보다 CLI 인자 방식이 더 적합합니다.

## 추천 다음 단계

1. 외부 EXE 런처에서 Python 엔진을 직접 실행할지, C#에서 프로세스로 호출할지 결정합니다.
2. 엑셀 엔진에 CLI 옵션을 추가합니다.
   - `--excel`
   - `--config`
   - `--output`
   - `--sheet`
3. 대형 집계표 성능 개선을 먼저 합니다.
4. VBA add-in 산출 시트와 Python 엔진 출력 포맷을 맞춥니다.
5. HWPX 직접 삽입은 그다음 단계에서 한글 COM API 또는 HWPX XML 생성 방식으로 분리 구현합니다.
