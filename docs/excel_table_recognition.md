# 집계표 형식 변형 인식

## 적용 범위

런처의 표·배너 미리보기, Excel 추가기능의 산출 시트 생성, Python의 원본 표 문장
추출에서 제목 문구 하나만으로 표를 판단하지 않는다. 제목 후보, 헤더와 실제 수치
구간의 연결을 확인한다. 기존 작업 복사본·셀 표시값·수동 범위 보정 흐름은 유지한다.

## 인식 근거

- `[표 1]`, `[ 표 1 ]`, `<표 1>`, `표 1.`, `Table 1.` 등 제목 표기를 허용한다.
- 제목이 A열이 아닌 B/C열에 있거나 병합되어 있어도 주변 표 구조를 확인한다.
- 표 번호 없는 문항 제목은 가까운 헤더와 데이터가 뒷받침할 때 후보로 사용한다.
- `사례수`, `표본수`, `응답수`, `빈도`, `N` 등의 헤더는 공백·줄바꿈·단위 표기를
  정규화해 비교한다. 본문에서 해당 단어를 언급한 것만으로 헤더로 취급하지 않는다.
- 익숙하지 않은 열 이름은 텍스트 헤더와 실제 항목별 숫자 행, 표 경계를 함께 확인한다.
  이때 열의 의미나 단위를 임의로 확정하지 않는다.
- 여러 헤더 행이 같은 첫 데이터 행으로 연결되면 한 표로 본다.
- 다음 표의 제목·헤더가 이전 표의 본문으로 들어가지 않도록 경계를 확인한다.
- 전체 행은 `■` 기호에만 의존하지 않는다. `전체`, `합계`, `Total` 등과 수치를 함께 확인한다.
- 배너는 상위 헤더와 하위 항목의 관계를 확인한다. `◐` 없는 배너도 후보가 될 수 있으나
  `%` 바로 위의 만족/불만족 같은 응답 선택지를 자동으로 상위 배너에 넣지 않는다.
- 목차·출처·주석·숫자 없는 안내문은 실제 데이터 행과 구분한다.

Python 추출에서는 열 이름과 실제 열 좌표를 함께 사용한다. 중간 빈 열이나 같은 이름의
응답 열 때문에 오른쪽 값이 왼쪽 항목에 잘못 연결되지 않도록 하며, 중복 이름은 구분한다.
실제 Excel 백분율 서식의 `0.633`은 분석 시 `63.3%`로 처리한다. 일반 숫자와 문자열의
리터럴 `%`는 구분하며, 원본의 실제값·표시값·숫자 서식은 바꾸지 않는다.
CLI 추출은 Tk GUI 라이브러리가 없어도 실행할 수 있다.

## 확인이 필요한 경우

런처 표 목록의 `인식 확인`에 제목 누락·구조 추정·비표준 헤더 등의 확인 사유를 표시한다.
VBA 산출의 표 목록/QA도 확인한다. 제목이나 열 의미가 불명확하면 원문을 검토하고
기존 `Excel에서 범위 다시 선택`으로 최종 범위를 보정한다.

원본 파일은 수정하지 않으며, 보정은 작업 복사본에서 산출에 사용할 범위를 지정하는 것이다.
형식이 생소하다는 이유로 첫 번째 숫자 열을 비율이나 점수로 무조건 사용하는 방식은 피한다.
표 인식 성공이 곧 문장·단위 해석까지 확정되었다는 뜻은 아니다.

## 검증

가짜 Excel 파일로 제목 표기, 이동한 열, 다단/병합 헤더, 기호 없는 전체/배너,
제목 누락, 빈 열·중복 열, 표 사이 공백, 목차 오탐과 값 대응을 검사한다.
실제 KISDI 집계표는 읽기 전용으로 기존 표 인식 여부를 확인한다.

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_excel_table_recognition.py -q
powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_excel_recognition_launcher.ps1
powershell -NoProfile -ExecutionPolicy Bypass -File tests/test_excel_recognition_vba.ps1
```

배포 EXE에는 최신 추가기능과 Python 엔진을 함께 묶는다. 소스 수정만으로 기존 EXE의
내장 파일이 바뀌지는 않으므로 추가기능 빌드 후 독립 실행 런처를 다시 빌드해야 한다.

## 현재 한계

자동 인식은 조사 집계표를 중심으로 한 규칙 기반 처리다. 모든 임의 Excel 배치를 이해하거나
단위를 추론하는 AI 기능은 아니다. 좌우로 나란히 배치된 독립 표, 중간에 삽입된 별도
설명 블록, 값의 의미가 명시되지 않은 표는 자동 범위와 QA를 검토해야 한다.
이러한 경우 원본을 임의로 재배치하거나 서로 다른 표를 강제로 합치지 않는다.
Python의 제목/헤더 연결 탐색은 내용이 있는 32개 행까지이며, 수식은 저장된 계산값을
사용한다. 복잡한 조건식이 있는 사용자 숫자 서식은 분석문과 실제 표시값을 비교해야 한다.
런처 미리보기의 기존 한도는 5,000행/300열이며, 더 큰 표는 수동 범위를 확인해야 한다.

## 2026-10-14 검증 기록

- 전체 Python 테스트: 208개 통과, 1개 건너뜀(Windows 심볼릭 링크 권한), subtest 32개 통과.
- 런처의 구조 인식 검사와 EXE 단독 실행 검사 통과. 단독 실행 검사는 숨김 GUI,
  내장 Python, 원본 집계표 문장 추출, 템플릿 생성·검사와 캐시 재사용을 확인한다.
- Excel/VBA 검사 통과: 변형 표, 실제 좌표, 전체 행, 배너, 수동 범위 보정 및
  읽기 전용 KISDI 원본의 127개 표 인식 확인.
- 별도 폴더에 복사한 EXE에서 검증된 D 드라이브 추가기능을 명시했을 때,
  가짜 표 3개를 Excel 산출 시트와 report package로 변환하는 흐름 통과.

미해결 통합 항목: 기본 로컬 캐시의 추가기능은 파일 존재와 원본과의 해시 일치가
확인되지만, 현재 PC의 Excel에서는 해당 경로를 열 때 파일을 찾을 수 없다는 COM
오류가 발생한다. 같은 파일의 D 드라이브 경로에서는 성공한다. 정확한 원인은
확정하지 않았으며, EXE 단독 실행 검사 통과를 Excel 자동화 전체 통과로 해석하면 안 된다.
사용자가 직접 확인한 추가기능 경로를 GUI에서 선택하거나 CLI의 `--addin`으로
지정할 수 있다. 이 검증에서 Office 신뢰 설정·매크로 보안·레지스트리는 변경하지 않았다.
다음 안정화 작업에서는 기본 캐시 경로의 Excel 접근/신뢰 여부를 별도로 진단해야 한다.
