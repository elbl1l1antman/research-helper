# Research Helper 런처 UX 개선 설계

- 상태: 개발 검토안. 실제 런처와 처리 엔진은 변경하지 않았다.
- 화면 검수: Windows의 0.0.53 독립 실행 런처에서 원본 파일, 표·배너, 보고서 설정, PPTX 차트 서식, 산출 결과, 기관 대시보드 화면을 열어 확인했다. 업무 파일을 새로 열거나 산출하지 않았다.

## 발견 사항

| 우선순위 | 확인한 문제 | 개선 기준 |
|---|---|---|
| P0 | 첫 화면에서는 `Excel 산출 시트 만들기`만 보인다. 주 업무인 HWPX를 고르려면 `보고서 설정 > 파일 · 서식`을 찾아야 한다. 해당 화면에는 실행할 수 없는 `PowerPoint 보고서`도 있다. | 첫 화면에서 `한글 보고서(.hwpx)`와 `Excel 산출 시트` 목적을 먼저 구분한다. 실제 지원하는 목적만 표시한다. |
| P0 | 산출 전 체크리스트는 양식 검사 상태를 표시하지만 버튼은 HWP 경로 존재 여부만 본다. 준비 상태와 누를 수 있는 행동이 다르다. | 준비 상태, 동작 버튼, 키보드 실행에서 같은 판단을 사용한다. 자동으로 처리할 수 있는 양식 검사는 별도 수동 절차를 강제하지 않는다. |
| P1 | 표·배너 화면에서 원본이 없는데 표·배너 도구들이 먼저 보인다. 체크한 배너 수와 하단의 `전체` 입력칸이 무엇을 뜻하는지 바로 구분하기 어렵다. | 원본 없음·탐지 중·실패·탐지 완료를 구분한다. 분석에 적용할 배너와 표 원본의 범위를 따로 표시한다. |
| P1 | 차트 서식을 고르는 콤보 옆에 사본 저장·등록·삭제·CRTX 변환이 모두 비슷한 버튼으로 있다. 서식의 색과 형태는 확인할 수 없다. | 작업 중에는 현재 적용 서식과 간단한 미리보기만 표시한다. 사본 저장·등록·삭제·변환은 `차트 서식 관리…`에 둔다. |
| P1 | 결과 탭은 실행 전 체크리스트, 완료 요약, 파일 버튼, 문장 탭, 로그를 한 화면에 섞는다. 원본에서 시작하는 차트 제작과 검토를 마친 PPTX의 EMF 저장도 같은 버튼 줄에 있다. | 산출 중에는 현재 단계와 최근 진행을, 완료 후에는 해당 산출물의 열기 버튼을 먼저 보인다. 실패 시 보존된 파일과 다음 조치를 표시한다. |
| P2 | 기관 대시보드가 보고서의 4단계와 같은 탭 줄에 있다. | 탭을 삭제하지 않고 별도 도구임을 표시한다. 데이터 매핑 흐름은 변경하지 않는다. |

코드 근거: `ReportAutomationLauncher.cs`의 `MainForm` 생성자, `UpdateWorkflowStatus`, `BuildOutputGroup`, `LoadWorkbookPreviewAsync`, `BuildSurveyChartStyleGroup`, `BuildRunGroup`, `RunButton_Click`, `LauncherOptions.Validate`.

## 권장안

색상만 바꾸면 준비 상태의 불일치가 남는다. 런처를 다른 프레임워크로 이전하면 Excel·한글 COM, DPI, 독립 실행 패키징을 모두 재검증해야 한다. **기존 WinForms의 탭과 핸들러를 유지하고, 작업 순서·버튼 계층·상태 연결만 바꾸는 안**을 권장한다.

```text
1 원본·산출물      [한글 보고서(.hwpx) | Excel 산출 시트]   [Excel 파일 선택…]
2 표·분석 배너     발견한 표 132개 / 배너 9개 / 선택 5개    [보고서 설정으로]
3 보고서 설정     한글 양식 / 본문·표 서식 / 삽입 범위      [한글 보고서 만들기]
4 결과            2 / 3 QA 검사 중 → 저장 완료            [한글 보고서 열기]
별도 도구          기관 대시보드 PPT
```

- `출력 폴더`는 원본을 고르는 화면에 유지한다. 비워둘 때 원본 폴더를 쓰는지, 수동 선택한 폴더를 쓰는지 및 `작업 복사본` 여부를 같은 줄에서 확인할 수 있게 한다.
- 한글 설정은 `양식·용지`, `분석문`, `표·그림` 순서다. 기존 스타일 창·실시간 예시·직접 지정 서식·용지 설정을 재사용한다. 한글 모드의 Excel은 내부 단계로 표시한다. Excel 모드에는 한글 전용 설정을 노출하지 않지만 값은 보존한다.
- 현재 HWPX 문항 범위 기본값은 `첫 문항`이다. 이를 바꾸지 않고 `첫 문항 / 처음 3문항 / 전체 문항`을 산출 직전에 표시한다. 배너 체크 해제·탐지 실패를 임의로 같은 `전체` 상태로 보이지 않게 한다. 범위 보정은 행 선택 후 사용하고, 원본 값이나 배너의 분석 의미는 바꾸지 않는다.
- 그림 삽입을 켠 경우 차트 서식(예: `딥 블루`, `스카이 블루`)을 인라인으로 표시한다. 샘플 이미지는 가짜 항목과 값으로 만든 표시용이며 실제 차트는 PPTX 편집 객체, 한글은 검증된 EMF 경로를 그대로 사용한다. 개인 서식의 실제 미리보기를 만들 수 없으면 다른 기본 서식의 미리보기로 대체하지 않는다.
- 결과는 `만드는 중`, `저장 완료`, `검토 필요`, `저장하지 못함`을 구분한다. 완료 메시지의 확인 버튼을 없애더라도 차트 수동 교체 경고와 복구 경로를 숨기지 않는다. `차트 검토 PPTX 만들기…`는 같은 실행의 보고서 데이터가 있을 때 활성화하고, `편집한 PPTX를 EMF로 저장…`의 기존 외부 패키지 선택 경로는 유지한다.

## 시각·접근성 기준

- UI UX Pro Max의 조밀한 업무 화면, 버튼 계층, 진행 표시, 보이는 키보드 포커스 규칙을 적용한다. 웹용 랜딩 페이지 패턴과 외부 폰트는 적용하지 않는다.
- 기존 `LauncherUi`의 맑은 고딕, 밝은 중립색과 짙은 녹색, 기본·보조·텍스트 버튼 토큰을 재사용한다. 배너 수치와 결과 상태는 색뿐 아니라 텍스트로 구분한다. 일반 텍스트 4.5:1, 포커스/의미 있는 컨트롤 경계 3:1을 목표로 실제 조합을 검사한다.
- 한 화면에 주 동작은 하나. 입력 바로 옆에 관련 동작을 배치하고, 저장 경로·오류 이유는 포커스로 접근 가능해야 한다. 메뉴에 들어간 파일 변환이나 삭제도 키보드로 접근하고, 취소 시 초점을 복원한다.
- 논리 최소 창 980×720, 100/125/150% 배율, 1366×768 물리 화면에서 검증한다. 최소 창이 작업 영역보다 커지는 조합은 스크롤로 하단 푸터까지 가리는 대신 작업 영역 크기를 기준으로 내부 콘텐츠만 스크롤시킨다.

## 제외 범위

Excel 표 인식, 보고서 문장, HWPX 표·차트·EMF 출력, PPTX 작성기, 재개 키/파일 분류, 저장 형식과 외부 라이브러리는 변경하지 않는다. 독립 EXE는 기존 단일 산출 방식으로 유지한다.
