# HWP Named Styles and Table Text Stabilization Design

## 1. 목적

HWP/HWPX 보고서 생성 과정에서 다음 문제를 함께 해결한다.

- 분석문 첫 문장과 후속 문장이 붙어서 출력되는 문제
- `(3,232)` 같은 Excel 표시문자가 `-3232`로 변환되는 문제
- 표에 포함된 장식용 특수기호가 그대로 출력되는 문제
- 본문과 표의 역할별 서식을 사용자가 선택하고 재사용할 수 없는 문제

결과 문서에는 다음 다섯 스타일이 아래한글 스타일 목록에 실제 이름으로 등록되어야 한다.

- `보고서 본문1`
- `보고서 본문2`
- `표보기`
- `표배너`
- `표숫자`

## 2. 범위

### 포함

- HWPX 스타일 정의 추가 및 갱신
- `.hwp` 템플릿의 임시 HWPX 변환 후 동일한 스타일 처리
- 분석문 블록 분리 및 역할별 스타일 적용
- Excel 표시문자 텍스트 보존
- 표 셀 특수기호 정제
- 역할별 표 스타일과 셀 외형 적용
- 런처에서 최대 3개의 사용자 프리셋 저장·선택·삭제
- 기본 프리셋 제공
- package, preflight, writer report에 적용 결과 기록

### 제외

- PPTX 스타일 변경
- Excel 원본 파일 직접 수정
- 기존 사용자 HWP/HWPX 템플릿의 디자인 품질 자동 평가
- 임의의 모든 유니코드 기호를 의미론적으로 분류하는 기능

## 3. 처리 흐름

```text
런처 스타일 프리셋 선택
  -> hwp_style_config.json 생성
  -> Excel 산출 시트 생성
  -> report_package.json 생성
  -> 표 표시문자 정제 및 QA
  -> HWP/HWPX 템플릿 작업 사본 준비
  -> HWPX에 다섯 개의 이름 있는 스타일 등록/갱신
  -> 아래한글 COM으로 본문·표 생성
  -> 문단 및 표 셀에 등록된 스타일 적용
  -> HWPX 저장 및 재개봉 검증
```

원본 Excel과 원본 템플릿은 수정하지 않는다.

      "font_size_pt": 10.0,
      "bold": false,
      "bullet": "-",
      "line_spacing_percent": 160,

      "first_line_indent_mm": -5.0,

    },
    "표보기": {
      "font_family": "맑은 고딕",
      "font_size_pt": 8.5,
      "bold": false,
      "bullet": "",

필수 스타일 이름은 고정한다. 사용자는 표시 속성만 변경할 수 있다.

## 5. 프리셋 저장 정책

- 기본 프리셋은 프로그램에 내장하고 삭제할 수 없다.
- 사용자는 별도의 사용자 프리셋을 최대 3개 저장할 수 있다.
- 저장 위치는 `%LOCALAPPDATA%\ResearchHelper\hwp_style_presets.json`이다.
- 프리셋 이름은 사용자 프리셋 사이에서 중복될 수 없다.
- 같은 이름으로 저장할 때는 명시적으로 덮어쓴다.
- 선택한 프리셋은 실행마다 `hwp_style_config.json`으로 출력 폴더에 기록한다.
- 프리셋 파일이 손상되면 기본 프리셋으로 복구하고 경고를 표시한다.

## 6. 분석문 블록 처리

`narrative_final` 원문은 package에 그대로 보존하고, writer용 `narrative_blocks`를 추가한다.

```json
[
  {"style": "보고서 본문1", "text": "전체 종사자 규모는 ... 가장 높게 나타남"},
  {"style": "보고서 본문2", "text": "다음으로 ... 순으로 나타남"}
]
```

분리 우선순위는 다음과 같다.

1. `CRLF`, `LF`, `CR`로 구분된 비어 있지 않은 줄
2. 줄바꿈이 유실된 기존 문장의 경계 복원
   - `나타남다음으로`
   - `나타남그다음으로`
   - `나타남반면,`
3. 경계가 없으면 전체 문장을 `보고서 본문1` 한 블록으로 유지

첫 블록에는 `보고서 본문1`, 이후 블록에는 `보고서 본문2`를 적용한다. 본문2의 말머리는 프리셋 값으로 한 번만 표시하며, 원문이 이미 같은 말머리로 시작하면 중복하지 않는다.

## 7. Excel 표시문자 보존

VBA의 `보고서_삽입표셀` 출력에서 다음 규칙을 적용한다.

- `display_text` 열은 쓰기 전에 Excel 셀 형식을 텍스트(`@`)로 고정한다.
- `Range.Text`를 문자열로 `Value2`에 기록한다.
- 문자형 `raw_value`는 대상 셀을 텍스트 형식으로 지정한 뒤 기록한다.
- 실제 숫자형 `raw_value`는 숫자형으로 유지한다.
- 빈칸, `0`, `-`, 괄호형 사례수는 서로 구분한다.

예:

```text
원본 표시값: (3,232)
display_text: (3,232)
raw_value: 3232 또는 원본 문자열
HWP 삽입값: (3,232)
```

Python은 `display_text`를 재해석하거나 숫자로 변환하지 않는다.

## 8. 표 셀 문자 정제

정제는 package 생성 시 한 번만 수행한다. 모든 writer는 정제된 `display_text`를 사용한다.

처리 순서:

1. `html.unescape`로 문자 엔티티 복원
2. 제어문자 제거
3. 장식용 유니코드 기호 범주 제거
4. 연속 공백 정리
5. 원문과 달라졌으면 셀 주소를 QA warning에 기록

허용:

- 한글, 영문, 숫자
- 공백
- `-`, `~`, 작은따옴표, 큰따옴표, 괄호, 쉼표, 마침표, 콜론, 세미콜론
- `%`, `+`, `=`, `/`, 통화 기호
- `℃`, `°`, `㎡`, `㎢`, `㎥`, `㎏`, `㎎`, `㎞`, `㎝`, `㎜`, `㏄` 등 일반 단위

제거:

- `●`, `■`, `◆`, `▶`, `※` 등 장식 표식
- 이모지 및 그림문자
- 비표시 제어문자

셀 값 전체가 제거되면 빈 문자열로 만들고 warning을 남긴다. `raw_value`와 원본 Excel은 변경하지 않는다.

## 9. 표 역할과 스타일 매핑

| 셀 역할 | 적용 스타일 |
|---|---|
| `banner_horizontal`, `base`, `title` | `표배너` |
| `banner_vertical`, `stub`, `note`, `source`, `unknown` | `표보기` |
| `value` | `표숫자` |
| `blank` | 주변 셀 역할을 우선하고 없으면 `표보기` |

아래한글 스타일은 글자·문단 속성을 포함한다. 셀 배경, 테두리, 세로 정렬은 같은 프리셋의 `table_cell_styles`와 `table_border`를 통해 별도로 적용한다.

## 10. HWPX 스타일 등록

권장 경로는 템플릿 작업 사본의 HWPX 스타일 정의를 생성 전에 보정하는 방식이다.

1. 원본 템플릿을 작업용 임시 파일로 복사한다.
2. `.hwp` 템플릿이면 아래한글 COM으로 임시 HWPX로 변환한다.
3. HWPX `header.xml`의 `charPr`, `paraPr`, `style` 목록을 읽는다.
4. 같은 이름의 스타일이 있으면 해당 참조 속성을 갱신한다.
5. 없으면 새 `charPr`, `paraPr`, `style`을 추가한다.
6. 스타일 인덱스와 이름 매핑을 writer에 반환한다.
7. COM writer는 `Style` Action의 `Apply` 인덱스로 문단과 표 셀에 적용한다.

원본 템플릿은 수정하지 않는다. XML 보정이 실패하면 문서 생성을 차단하며, 이름 없는 직접 서식 적용으로 조용히 대체하지 않는다.

## 11. 런처 UI

HWPX 옵션 영역에 다음을 추가한다.

- 프리셋 선택 콤보박스
- `서식 설정` 버튼
- 현재 프리셋 상태 표시

서식 설정 창:

- 본문 스타일 탭: 글꼴, 크기, 굵게, 말머리, 줄간격, 왼쪽 들여쓰기, 첫 줄 들여쓰기
- 표 스타일 탭: 글꼴, 크기, 굵게, 정렬, 배경색
- 표 공통 탭: 내부선, 외곽선, 선 색상
- 프리셋 이름
- 저장, 덮어쓰기, 삭제, 기본값 복원

숫자 입력은 허용 범위를 벗어나면 저장하지 않는다.

- 글자 크기: 6~30pt
- 줄간격: 80~300%
- 들여쓰기: -30~100mm
- 선 굵기: 0.1~5.0mm

## 12. Preflight 및 리포트

차단 조건:

- 필수 다섯 스타일 중 하나가 없음
- 스타일 XML 등록 실패
- 프리셋 JSON 파싱 실패 후 기본값 복구도 실패
- 스타일 인덱스를 찾을 수 없음
- 문장 블록이 모두 비어 있음

경고 조건:

- 특수기호가 제거된 셀
- 줄바꿈 경계를 자동 복원한 문장
- `unknown` 역할 셀
- 템플릿 기존 스타일을 사용자 프리셋으로 갱신함

writer report에는 다음을 기록한다.

- 선택 프리셋 이름
- 등록·갱신된 스타일과 인덱스
- 본문1/본문2 적용 문단 수
- 표보기/표배너/표숫자 적용 셀 수
- 정제된 셀 수와 주소
- fallback 또는 실패 원인

## 13. 테스트

### 단위 테스트

- CRLF/LF/CR 문장 분리
- `나타남다음으로` 경계 복원
- 말머리 중복 방지
- `(3,232)` 표시문자 보존
- `●` 제거 및 허용 문장부호·단위 보존
- 셀 역할별 스타일 이름 매핑
- 사용자 프리셋 3개 제한

### 통합 테스트

- 기본 HWPX 템플릿에 다섯 스타일 등록
- 같은 이름의 기존 스타일 갱신
- `.hwp` 템플릿을 HWPX로 변환 후 스타일 등록
- 본문1/본문2가 별도 문단으로 생성됨
- 표 셀별 스타일 적용
- 문서를 다시 열어 스타일 목록과 표 객체 확인
- 원본 Excel과 템플릿 불변 확인

### 실제 자료 검증

KISDI 집계표에서 표 3개를 선택해 다음을 확인한다.

- 괄호형 사례수 유지
- 장식 기호 제거
- 다단 가로배너와 세로배너 유지
- 본문 두 문단 분리
- 문서 스타일 목록에 다섯 스타일 존재
- UI에서 저장한 프리셋을 재실행 시 재사용 가능

## 14. 완료 기준

- 사용자 프리셋을 최대 3개 저장하고 선택할 수 있다.
- 결과 HWPX의 스타일 목록에 다섯 스타일이 실제 등록된다.
- 분석문 첫 문장과 후속 문장이 분리된다.
- `(3,232)`가 음수로 변환되지 않는다.
- 표의 장식용 특수기호가 제거된다.
- 표 역할별 스타일과 셀 외형이 적용된다.
- 재개봉 검증과 기존 HWP writer 회귀 테스트를 통과한다.
