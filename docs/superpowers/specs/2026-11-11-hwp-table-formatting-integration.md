# 한글 표·서식 개선 설계

> 초기 비교 기록이다. 실제 지원 범위, 서식 우선순위, 구현·검수 기준은 [개정 계획](../plans/2026-11-11-hwp-table-formatting-revision.md)을 따른다.

## 출처와 범위

- 입력 자료: 사용자가 첨부한 `범피스_한글기능_역설계.md`, [한글 서식과 표 기능 역설계](codex://threads/6af3be0d-d230-8191-9353-3b8a3497f08d?hostId=durable) 세션.
- 비교 기준: `research-helper`의 `bd99f90`. 역설계 자료의 COM 호출은 정적 관찰이며, 한글 버전별 동작이나 출력 서식의 실측값이 아니다. 자료의 수치와 설계 제안은 요구사항이 아니다.
- 사용자 제공 자료는 기능 비교에만 사용한다. 외부 실행 파일, 추출 코드·리소스, 기관별 스타일을 가져오거나 배포하지 않는다. 구현은 프로젝트 코드와 한컴 API 문서에 근거한다.

## 이번 단계의 동작 계약

1. **표 입력 실패는 산출 중단.** `InsertText`, 확정된 셀 이동·선택·병합이 실패하면 뒤 작업을 하지 않는다. 표 식별자·분할 번호·실패 액션을 기록한다. 클립보드 대체는 변경이 없거나 기존 정책으로 붙여넣기를 되돌린 경우에만 허용한다. TableCreate를 호출한 뒤 상태를 확인할 수 없으면 재시도·텍스트 대체 없이 중단한다. 원본 및 이미 존재하는 출력 파일을 실패 중 저장하지 않는다.
2. **저장된 HWPX 기준 검증.** 합성 집계표에 기존 작성기를 사용하고 XML에서 개별 표, 논리 행·열, 셀 좌표·병합, 표시값, 머리행 플래그, 본문 폭을 확인한다. 실제 한글에서 다시 열어 줄바꿈·페이지 넘김·표지/꼬리말과 글꼴을 확인한다. 구조 검사와 화면 검사는 결과를 분리 기록한다. 이번 단계에서는 이 검사를 개발 검증에 적용하고 모든 사용자 출력의 저장 경로는 변경하지 않는다.
3. **선 표시 옵션.** 기존 `table_border`에 `inner_type`, `outer_type`을 추가한다. 각각 `solid` 또는 `none`이며 누락 기본값은 `solid`이다. `show_side_borders=false`이면 외곽 좌우를 숨기고, BASE 메타 행은 모든 옵션과 관계없이 무테두리다. 색상, 굵기, 바탕, 기존 이름 스타일과 프리셋 3개 제한은 유지한다. 한글에서 실제 양방향 경계가 올바르게 저장되는 것을 확인한 뒤 배포한다.

## 유지·보류

- Windows + 설치된 한글 + 기존 pywin32, HWPX 출력, 기존 HWP 입력의 HWPX 변환 경로를 유지한다. Python 배포 빌드 조건은 기존 Windows x64 3.12 이상이다. 새 의존성과 새 문서 백엔드를 추가하지 않는다.
- 원본 Excel·템플릿 불변, 사전검증 차단 준수, 작업 사본 사용, 표의 `display_text` 보존, 그림/OLE 대신 편집 가능한 표 객체, 본문 한 단, 기본 좌우 외곽선 숨김, `[BASE : 전체 | 단위 : 명]` 형식을 유지한다. 현재 보안·권한 설정을 바꾸지 않는다.
- Excel 캐시 접근 문제, PPTX, 새 파일 포맷, 전체 양식 복제, 기존 사용자의 활성 문서 편집, 새 `DocumentBackend`는 범위 밖이다. 셀 여백·고정 행 높이와 점선·이중선은 추후 검토한다. 여백은 양 삽입 경로의 열 폭·줄바꿈 계산에 영향을 주므로 단순 속성 추가로 처리하지 않는다.
- 한글이 없는 환경에서는 구조 테스트만 완료할 수 있다. 실제 한글 검증이 끝나기 전에는 렌더링 확인이나 배포 완료로 표기하지 않는다.
