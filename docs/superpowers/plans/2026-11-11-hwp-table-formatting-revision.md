# HWPX 서식 재현 및 실제 보고서 검수 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사용자가 지정한 보고서 서식을 실제 집계표의 역할과 병합 구조에 맞춰 적용하고, 저장된 HWPX에서 설정값과 모양을 확인한다.

**Architecture:** 역설계 관찰, 현재 구현, 원하는 결과를 분리한다. 기존 `report_package`의 논리 좌표와 표시값을 그대로 사용한다. 사용자가 저장하는 프리셋에서 서식을 한 번 결정한 뒤 두 표 삽입 경로에 공통 적용한다.

**Tech Stack:** Windows, 설치된 한글 COM/pywin32, Python, HWPX ZIP/XML, 기존 C# WinForms 프리셋.

**Spec:** [초기 비교 기록](../specs/2026-11-11-hwp-table-formatting-integration.md), [한글 서식과 표 기능 역설계](codex://threads/6af3be0d-d230-8191-9353-3b8a3497f08d?hostId=durable), 이 문서의 서식 계약과 완료 기준.

## Global Constraints

- 원본 Excel·템플릿 불변, 새 HWPX 산출, 편집 가능한 표 객체, Excel 표시값 우선. 기존 스타일 이름과 사용자 프리셋 3개 제한을 유지한다.
- 기존 프리셋을 열면 새 옵션은 현재 동작을 기본값으로 한다. 값을 정할 수 없는 서식은 템플릿 기본값을 유지하며, 다른 값으로 조용히 대체하지 않는다.
- 외부 프로그램의 코드를 복사하거나 배포하지 않는다. 현재 PC에서 그 실행 파일을 자동 실행하지 않는다. 한컴 API 문서와 합성 문서로 독립 검증한다.
- 단계별 커밋. 구현 승인 전 제품 코드와 배포 EXE는 변경하지 않는다. 구조 검사와 실제 한글 열기 검사는 각각 기록한다.

## Review Focus

- 범피스의 상수·액션 이름을 확인한 것과, 선택 영역·단위·저장 결과를 확인한 것은 다르다. Task 1.
- 대표 배경색을 헤더 배경색으로 가져오면 본문에 더 많은 흰색이 선택될 수 있다. Task 2.
- 같은 셀의 배경과 테두리를 연달아 적용할 때 뒤 액션이 앞 결과를 지우거나 이웃 셀 선을 바꿀 수 있다. Task 3.
- 셀 여백을 늘리면 줄바꿈, 열의 실제 폭, 병합 표의 분할 결과가 달라진다. Task 3.
- XML이 유효해도 페이지 반복 머리행, 긴 한글 줄바꿈과 글꼴 대체는 화면에서 깨질 수 있다. Task 4.

## Task 2: 역할별 프리셋과 템플릿 가져오기

**Files:** `hwp_style_config.py`, `hwpx_style_registry.py`, `hwp_template_probe.py`, `hwp_template_table_recognizer.py`, `ReportAutomationLauncher.cs`의 기존 서식 편집기 및 해당 테스트.

[구현·검증 기록](../../hwp_role_styles.md). 기존 스타일 설정 구조를 확장해 별도 스키마를
만들지 않았다. 사용자 선택 셀의 속성은 기존 탐색기의 최빈값 처리와 분리했다.

- [ ] 기존 5개 이름 스타일은 유지한다. 셀 적용 역할은 `metadata`, `header`, `banner_horizontal`, `banner_vertical`, `stub`, `base`, `value`로 구분한다. `metadata`는 생성용 BASE 안내행, `base`는 원본 사례수/BASE 데이터다. 여러 페이지에 반복할 수 있는지는 `header_row_count`로만 판단하고, 시각적인 역할을 그 값으로 덮지 않는다.
- [ ] 선택 역할마다 기존 프리셋의 글꼴·크기·굵기·가로/세로 정렬·배경을 기본으로 사용하고, 지정한 값만 덮는다. 기본은 기존 `표배너`/`표보기`/`표숫자` 매핑이다. 머리행과 배너가 서로 다른 색·정렬을 가질 수 있어야 한다. 임의 좌표별 편집기는 이번 범위 밖이며, 템플릿에서 사용자 지정 역할을 매핑하는 방식으로 셀을 지정한다.
- [ ] 선택한 HWPX 표에서 대표 셀의 `cellAddr`, 병합 span, `borderFillIDRef`, `charPrIDRef`, `cellMargin`, 정렬을 읽는다. 최빈값이 아닌 사용자가 고른 머리행·배너·값 셀에 연결한다. 읽은 값은 미리보기에서 확인한 뒤 프리셋에 저장한다. 적용 우선순위는 **기본값 → 사용자가 가져와 저장한 값 → 사용자가 변경한 값**이다. BASE 안내행 오른쪽 정렬·무테두리 등 보호 규칙은 최종 적용한다.
- [ ] 검증: 헤더 2셀은 `E7E7E7`, 값 셀 10개는 `FFFFFF`인 템플릿에서 헤더 값은 `E7E7E7`로 가져온다. 헤더를 `DDEBF7`로 편집·저장·재열기한 후에는 `DDEBF7`이 적용된다. 역할 미지정·지원하지 않는 값은 미리보기에서 명시한다. 옛 프리셋 3개를 읽고 저장한 뒤 기본 출력이 변하지 않는지 확인한다.

## Task 3: 두 경로 공통 적용과 실패 방지

**Files:** `hwp_com_writer.py`, `hwp_table_layout.py`, `hwp_style_config.py`, 기본 스타일 JSON, `ReportAutomationLauncher.cs`, `tests/test_hwp_com_writer_styles.py`, `tests/test_hwp_table_layout.py`.

- [ ] [이전 계획의 Task 1](2026-11-11-hwp-table-formatting-integration.md)을 수행한다. 입력·선택·병합이 실패하면 후속 입력과 저장을 막는다. 다른 표에 들어가거나 불확실한 붙여넣기 상태에서 대체 표를 추가하지 않는다.
- [ ] 프리셋에 `outer`, `inner_horizontal`, `inner_vertical`, `header_bottom` 선 그룹을 둔다. 각 그룹은 선 종류·굵기(mm)·색을 지정할 수 있다. 기본은 기존 선 정책을 유지한다. 같은 공유 경계에서는 `header_bottom`이 내부 가로선보다 우선하고, 양쪽 셀에 같은 결정을 적용한다. 좌우 외곽선 숨김과 BASE 안내행 무테두리는 더 높은 우선순위다. 셀 배경을 먼저 적용하고 테두리 적용이 그 배경을 지우지 않는지 확인한다.
- [ ] 셀 여백은 상/하/좌/우 mm로 설정한다. 지정하지 않은 경우 기존 여백 유지. 너비 계획에서 `셀 전체 폭 - 좌우 여백`을 내용 폭으로 사용한다. 표 생성의 열 폭 산식과 클립보드 임시 표의 줄바꿈 높이를 같은 결정값으로 계산한다. 여백을 뺀 값이 0 이하인 셀은 HWP에 삽입하기 전에 차단한다. 병합 셀은 병합 전체 폭을 사용한다.
- [ ] 검증: 머리행 아래가 외곽선과 다른 색·굵기여도 이어지는 페이지에서 유지, 숨긴 내부 세로선과 표시한 내부 가로선이 교차해도 의도대로 저장, BASE 안내행 무테두리·오른쪽 정렬 유지. 좌우 여백 합이 가용 폭과 같을 때 차단. 두 경로의 셀 앵커와 표시값은 동일하며 모르는 속성을 `applied`로 기록하지 않는다.

## Task 4: 실제 Excel과 양식으로 검수

**Files:** `hwp_com_smoke.py`와 [이전 계획의 Task 2](2026-11-11-hwp-table-formatting-integration.md), `docs/hwp_template_table_insertion_plan.md`, 검증 산출물 폴더.

- [ ] 합성 표로 셀 표시값, 원래 논리 좌표, 병합, 머리행 플래그, 본문 폭을 자동 검사한다. 추가로 `header.xml` 참조를 따라 역할별 글꼴·배경·선·여백을 확인한다. `(3,232)`, `3.3`, `0`, 빈칸을 각각 비교한다.
- [ ] **실제 시험 입력:** 앞서 제공된 KISDI Excel에서 다단 가로배너가 있는 표 1개와 긴 세로배너·다페이지 표 1개를 골라 표 키와 Excel 범위를 기록한다. 한글 양식 1개에 같은 데이터로 변경 전/후 HWPX를 생성하고 원본은 해시가 유지되는지 검사한다. 기준 양식이 확정되지 않으면 보유 양식으로 검증하고 원하는 디자인 일치 여부는 별도로 보류한다.
- [ ] 결과를 한글에서 다시 열어 표가 분리됐는지, 제목/본문과 표 순서, 표지/꼬리말, 한글+영문 글꼴, 줄바꿈·페이지 넘김, 머리행 반복, 가로 분할, 두 삽입 경로의 값과 서식 일치를 확인한다. 자동 검사 결과·한글 버전·사용 프리셋·HWPX 경로·검수 화면을 함께 기록한다.
- [ ] **완료 판정:** 합성 검증과 실물 검수 둘 다 통과해야 지원 완료로 표기한다. 구조만 맞거나 설치/캐시 문제로 화면 확인을 못한 항목은 보류로 남긴다. 성공한 범위에 대해서만 배포 EXE를 갱신하고 커밋한다.
