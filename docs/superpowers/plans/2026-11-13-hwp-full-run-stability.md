# HWPX 전체 산출 안정화 계획

검증에서 웹툰 XLS 작업본이 Excel에 열린 상태로 QA에 넘어가 파일 잠금이 발생했다. KISDI는 미리보기 52개와 실제 산출 132개가 달랐고, 두 번째 문항(103×103셀, 19개로 가로 분할)에서 문항 단위 로그가 오래 갱신되지 않았다. 전체 산출 제한 시간 뒤 최종 HWPX가 확인되지 않았다.

## 구현과 검증

- [x] **Excel → QA:** `AutomationRunner`에서 저장한 파일을 닫고 Excel을 종료한 뒤 반환한다. `EngineRunner`는 마지막 단계 이후에만 사용자가 요청한 Excel을 다시 연다. QA 실패 시에도 이미 저장된 파일을 열 수 있게 하며, 다시 열기 실패가 원래 결과를 덮지 않게 한다.
- [x] **표 목록:** `BannerInspector`는 서식만 적용한 빈 꼬리 영역을 제외하고 실제 값 범위를 여러 묶음으로 읽는다. 탐지기가 연속된 범위를 사용하도록 하여 묶음 경계를 가로지르는 표가 끊기지 않게 한다. 지나치게 큰 범위는 일부를 목록으로 내놓지 않고 이유를 알린다. 5,000행 이후, 300열 이후, 500번째 이후 표를 회귀 테스트한다.
- [x] **한글 진행과 실패:** 작성 로그에 진행 중인 문항/분할, 셀 좌표, 처리 단계와 완료 수를 저장한다. 런처는 동일한 진행 기록을 읽어 화면에 표시하고, 10분간 기록 갱신이 없을 때만 중단한다. 중단 상태를 JSON에 저장하고 완료 파일과 구분한다. 표시값을 다시 쓰는 기존 경로는 유지하고, Excel 임시 표의 동일한 행 높이와 열 너비 계산을 묶어 호출을 줄인다.
- [x] **확인 및 빌드:** Python 222개 통과(1개 건너뜀), 런처 미리보기/진행 감시 검사와 독립 실행 빌드 검증 완료. KISDI 실자료에서 132개와 52·53번째 표 범위 확인. 웹툰 XLS 한 문항에서 Excel 닫기 → QA → HWPX 저장 → Excel 다시 열기 순서와 231개 셀 표시값·병합 좌표를 확인했다. 검증 자료와 산출 로그는 저장소에 올리지 않는다.

## 남은 검증

- KISDI 132문항 및 지역서점 전체 재산출의 완료 여부와 실제 소요 시간은 이번 변경에서 확인하지 않았다. 셀 진행이 이어지는 대형 문서는 30분을 넘길 수 있다.
- 작업 중 부분 HWPX 저장과 자동 재개, 여러 한글 작성기의 클립보드 사용 직렬화는 이번 범위에서 제외한다.

BASE와 분석문 수치 경고는 Excel 형식별 정답 대조 후 별도로 수정한다. 경고를 없애기 위해 추정한 BASE를 채우지 않는다.

## 후속 보완 (0.0.42)

- [x] 진행 감시는 기록 파일을 잠시 읽지 못하거나(접근 거부, 형식 오류) 교체 중이어도 다음 폴링에서 다시 읽는다. 이전에는 IOException 외 예외가 감시를 끝내 Python 작성기가 감시 없이 남고, 한글 작성 잠금 때문에 다음 실행이 막힐 수 있었다.
- [x] 감시 자체가 예외로 끝나면 작성 프로세스를 종료한 뒤 오류를 전달한다. 중단 기록은 마지막 기록을 읽지 못해도 저장한다.
- 검증: Mono C# 5 컴파일과 반사 호출로 잘못된 중간 기록 허용, 갱신 없는 작성기 중단 기록을 확인. Windows `tests/test_hwp_writer_watchdog.ps1`은 EXE 재빌드 후 실행 필요.
