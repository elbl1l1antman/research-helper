# HWP/HWPX 보고서틀 기반 표 삽입 개발 계획

## 1. 검토 목적

현재 HWPX writer는 `{{BODY}}` 위치에 제목, 분석문, 표를 순서대로 새로 입력하는 방식이다. 그러나 제공된 실제 보고서틀을 보면 통계표는 단순히 본문 뒤에 붙는 객체가 아니다.

실제 보고서의 반복 단위는 다음에 가깝다.

```text
문항/소절 제목
분석문
그림 제목 또는 차트 캡션
Base/단위 표기
차트 영역
표 제목
보고서 삽입용 집계표
출처/주석
```

따라서 다음 개발 목표는 “표 객체를 새로 하나 만드는 것”이 아니라, 사용자가 제공한 HWP/HWPX 보고서틀에서 이 반복 블록을 인식하고, Excel 집계표 데이터를 해당 블록 구조에 맞춰 채우는 것이다.

## 2. 검토한 보고서틀

원본은 수정하지 않았다. HWP 파일은 아래한글 COM으로 HWPX 사본을 만들어 분석했다.

분석 산출물:

```text
outputs/hwp_template_probe/hwp_template_probe_report.json
outputs/hwp_template_probe/hwp_template_probe_summary.json
outputs/hwp_template_probe/converted_hwpx/
```

검토 파일:

| No | 파일 | 형식 | 분석 결과 |
|---:|---|---|---|
| 1 | 경기 웹툰 웹소설 불공정 실태조사 | HWP→HWPX | 표 22개, 실제 집계표 후보 6개 |
| 2 | 국립암센터 암검진 수검행태조사 | HWPX | 표 121개, 조사 결과표 패턴 다수 |
| 3 | 오픈마켓 해외배송 | HWP→HWPX | 표 235개, 구형 빈도/비율 표 패턴 |
| 4 | 해외 배송대행 | HWP→HWPX | 표 236개, 구형 빈도/비율 표 패턴 |
| 5 | 2024 지역서점 실태조사 이용자조사 파트 | HWPX | 표 51개, 디자인/목차/결과표 혼합 |
| 6 | 성장호르몬 주사제 보호자 조사 | HWP→HWPX | 표 18개, 기본 디자인 템플릿 성격 |

## 3. 확인된 핵심 구조

### 3.1 표가 모두 분석표는 아니다

HWP/HWPX 문서 안의 `표` 객체 대부분은 실제 통계표가 아니다.

다음 객체도 HWP 내부에서는 모두 표로 잡힌다.

- 표지 레이아웃
- 제출문/발간 정보 박스
- 목차/표목차/그림목차
- 챕터 표지
- 그림 제목 박스
- Base/단위 박스
- 빈 차트 자리
- 푸터/저작권 박스

따라서 writer는 “문서 안 첫 번째 표에 데이터 삽입” 같은 방식으로 가면 안 된다. 먼저 표 객체를 `layout`, `toc`, `figure_caption`, `chart_placeholder`, `result_table`, `summary_box`로 분류해야 한다.

### 3.2 실제 결과표는 크게 세 유형이다

#### A. 최신 조사 결과표형

국립암센터 템플릿에서 가장 명확하게 확인된다.

```text
폐암 검진 여부
Base | 40대 이상 응답자(n=3,664), 단위 | n, %

구분 | 사례수 | 예 | 아니오
    |       | n | % | n | %
전체 | (3,664) | (1,333) | 36.4 | (2,331) | 63.6
성X연령 | 남성 | 40대 | (546) | (310) | 56.8 | (236) | 43.2
```

특징:

- 표 제목과 Base/단위가 표 상단 또는 직전 블록에 분리되어 있음
- 헤더가 2단 이상임
- 응답 선택지마다 `n/%` 한 쌍을 가짐
- 행 배너가 2~3열 구조임
- `전체` 행과 배너 그룹 행이 구분됨

#### B. 구형 빈도/비율형

해외배송 계열 템플릿에서 확인된다.

```text
[표- ] 오픈마켓 구매 전 해외구매대행 인지
(단위:명, %)

      | 빈도 | 예 | 아니오
전체  | 700  | 88.1 | 11.9
성별 | 남자 | 290 | 88.3 | 11.7
     | 여자 | 410 | 88.0 | 12.0
```

특징:

- 표 제목은 `[표- ]` 또는 `[표-29]` 형식
- Base보다 `(단위:명, %)`가 우선 표기됨
- 응답값은 대체로 비율 중심이고 N은 `빈도` 열 하나로만 존재함
- 기존 보고서 표는 차트 바로 뒤에 오는 경우가 많음

#### C. 디자인 템플릿 placeholder형

성장호르몬/지역서점 템플릿에서 확인된다.

```text
표제목 입력
입력 | 입력 | 입력
```

특징:

- 실제 통계표가 아니라 스타일 복사용 원형에 가깝다
- 데이터 매핑 근거로 쓰면 안 됨
- 표 선, 글꼴, 제목 위치, 여백, 색상, 표 폭을 복제하기 위한 style source로 써야 함

### 3.3 표 앞에는 대개 차트/그림 블록이 있다

여러 템플릿에서 다음 패턴이 반복된다.

```text
분석문
[그림- ] 또는 그림 1-
(단위:%) 또는 [BASE : 전체 | 단위 : %]
차트 자리
[표- ] 또는 【표 2- 】
집계표
```

즉, HWP 보고서 writer는 `TABLE`만 삽입하는 것이 아니라 `CHART_BLOCK + TABLE_BLOCK`을 하나의 반복 단위로 다뤄야 한다. HWP v1에서 차트를 직접 삽입하지 않더라도 차트 자리와 캡션은 유지해야 한다.

### 3.4 Excel 집계표 구조 보존이 필요하다

보고서 삽입용 표는 Excel 원표를 단순한 `category/percent/raw_n` 목록으로 바꾸면 안 된다.

보존해야 하는 구조:

- 표 제목
- Base 문구
- 단위 문구
- 헤더 행 전체
- `n/%` 하위 헤더
- 응답 선택지별 병합 구조
- 행 배너 그룹명
- 행 배너 세부 항목
- 전체 행
- 빈 셀/병합 셀 위치
- 소수점 자리
- 원자료 출처 범위

따라서 `report_package.json`의 `tables[].rows`는 현재보다 확장되어야 한다.

## 4. 개발 방향 수정

### 기존 방향의 문제

현재 writer는 다음 방식에 가깝다.

```text
title
narrative
simple table: 항목 | 비율 | 가중 N | 원 N
source
```

이 방식은 빠른 smoke test에는 유효하지만, 실제 보고서틀에는 맞지 않는다. 실제 보고서에는 `항목/비율/가중N/원N` 표가 아니라, 다단 헤더와 배너 그룹을 가진 보고서용 집계표가 들어간다.

### 수정 방향

앞으로 HWPX writer는 다음 방식으로 바꾼다.

```text
Excel 산출 시트
→ ReportPackage v2
→ Template Blueprint
→ Section Render Plan
→ HWP COM Writer
```

핵심 원칙:

- Excel 표 구조를 잃지 않는다.
- HWP/HWPX 템플릿에서 반복 블록과 스타일을 먼저 인식한다.
- 사용자가 어느 반복 블록을 사용할지 확인할 수 있게 한다.
- writer는 새 디자인을 만들지 않고, 템플릿의 표/캡션/차트 영역을 복제해서 채운다.

## 5. 신규/개선 모듈 계획

### 5.1 `hwp_template_probe.py`

현재 1차 구현 완료.

역할:

- HWP 파일을 HWPX 사본으로 변환
- HWPX 내부 XML에서 표, 문단, 주변 텍스트 추출
- 표 후보를 1차 분류
- 분석 리포트 JSON 생성

다음 개선:

- 셀 병합/rowspan/colspan 추출
- 표 선/배경/글꼴/문단 정렬 추출
- 캡션과 실제 표 연결
- 차트 자리/그림 자리 구분
- 반복 블록 후보 추출

### 5.2 `template_blueprint.py`

신규 개발.

역할:

- `hwp_template_probe_report.json`을 읽어 문서 구조를 blueprints로 정규화
- 표지/목차/챕터/본문 반복 블록/부록 블록 분리
- 사용자에게 사용할 반복 블록 후보 제안

출력 예:

```json
{
  "template_type": "survey_report_hwp",
  "blocks": [
    {
      "block_id": "RESULT_BLOCK_001",
      "type": "question_result",
      "sequence": [
        "section_title",
        "narrative",
        "figure_caption",
        "chart_placeholder",
        "table_caption",
        "result_table",
        "source_note"
      ],
      "style_source": {
        "table_index": 18,
        "caption_index": 17
      }
    }
  ]
}
```

### 5.3 `report_package_v2`

현재 package의 `tables[].rows`를 확장한다.

필수 구조:

```json
{
  "table_key": "T001",
  "title": "폐암 검진 여부",
  "base": "40대 이상 응답자(n=3,664)",
  "unit": "n, %",
  "table_shape": {
    "header_rows": [
      ["구분", "사례수", "예", "", "아니오", ""],
      ["", "", "n", "%", "n", "%"]
    ],
    "body_rows": [
      ["전체", "", "(3,664)", "(1,333)", "36.4", "(2,331)", "63.6"],
      ["성X연령", "남성", "40대", "(546)", "(310)", "56.8", "(236)", "43.2"]
    ],
    "merge_plan": []
  },
  "source_range": "보고서_삽입표!A1:H44"
}
```

### 5.4 `hwp_result_block_writer.py`

신규 개발 또는 `hwp_com_writer.py` 확장.

역할:

- `Template Blueprint`의 반복 블록을 복제
- `ReportPackage v2`의 section/table/chart 데이터를 블록에 주입
- 템플릿 표 스타일을 복제한 뒤 셀 데이터만 교체
- 차트 직접 삽입 전까지는 차트 자리와 캡션을 유지하고 `[차트 삽입 필요]`를 명확히 표시

## 6. 사용자 GUI 흐름 수정

### 6.1 템플릿 등록 단계

사용자가 HWP/HWPX 보고서틀을 선택하면:

1. HWP면 HWPX 사본으로 변환
2. 템플릿 분석 실행
3. 반복 블록 후보 표시
4. 실제 결과표 후보와 레이아웃용 표를 구분 표시
5. 사용자가 “이 블록을 문항별 반복 블록으로 사용” 선택

표시해야 할 정보:

- 표 제목 후보
- Base/단위 후보
- 표 행/열 수
- 헤더 구조
- 차트 자리 존재 여부
- 표 앞뒤 문단
- 스타일 원본 표 번호

### 6.2 Excel 집계표 등록 단계

Excel 산출 시트를 읽으면:

1. 보고서 삽입용 집계표 후보 표시
2. 표별 헤더/배너 구조 미리보기
3. 사용자 선택 배너 반영
4. 어떤 표를 HWP에 넣을지 선택
5. 표별 차트 생성 여부 선택

### 6.3 매핑 단계

사용자가 확인해야 할 매핑:

| 항목 | 사용자 확인 필요 |
|---|---|
| HWP 반복 블록 | 어떤 디자인 블록을 반복할지 |
| 표 스타일 원본 | 어떤 표 서식을 복제할지 |
| 차트 자리 | 유지/문구 표시/나중에 삽입 |
| 표 제목 번호 | 자동 번호/원본 유지/사용자 지정 |
| Base/단위 | Excel 값 사용/템플릿 문구 유지 |
| 배너 | 전체/선택 배너/순서 조정 |

## 7. 개발 단계

### Phase 1. 템플릿 분석 정확도 개선

- HWP/HWPX 변환 및 분석 도구 정식화
- 표 객체를 레이아웃/목차/캡션/차트/결과표로 분류
- 셀 병합, 선, 배경, 글꼴, 정렬 추출
- 분석 결과를 GUI에서 확인 가능한 JSON으로 저장

완료 기준:

- 제공한 6개 보고서틀에서 결과표 후보와 레이아웃 표를 구분할 수 있음
- 반복 블록 후보를 최소 1개 이상 제안할 수 있음

### Phase 2. Excel 집계표 구조 보존

- `보고서_삽입표`를 단순 row 목록이 아니라 표 모양 그대로 package화
- 다단 헤더와 배너 그룹 유지
- Base/단위/출처 범위 저장
- 기존 `항목/비율/가중N/원N` simple table은 fallback으로만 유지

완료 기준:

- 국립암센터형 `구분/사례수/응답 n/%` 구조를 JSON으로 보존
- 해외배송형 `빈도/응답 비율` 구조를 JSON으로 보존

### Phase 3. HWP 반복 블록 기반 writer

- `{{BODY}}` 위치에 새 표를 만드는 방식에서 벗어남
- 템플릿의 반복 블록을 복제하고 내부 placeholder/표를 교체
- 표 제목, 분석문, 차트 자리, 표, 출처를 한 단위로 생성

완료 기준:

- 제공된 템플릿 중 1개를 선택해 실제 한 문항짜리 결과 페이지를 생성
- 사용자가 HWP에서 열었을 때 기존 템플릿 디자인과 같은 문서 흐름으로 보임

### Phase 4. 차트/그림 처리

HWP 차트는 즉시 직접 삽입하지 않는다.

우선순위:

1. 차트 캡션과 빈 차트 자리 유지
2. Excel/PowerPoint에서 만든 차트를 EMF로 선택 붙여넣기
3. 한글 COM 차트 객체 자동화 검토

완료 기준:

- 차트 직접 삽입 전에도 보고서 구조가 깨지지 않음
- 차트 미삽입 상태가 QA에 명확히 표시됨

### Phase 5. 실사용 검증

각 템플릿별로 한 문항짜리 데모를 생성한다.

검증 항목:

- 표 제목 위치
- 분석문 위치
- 그림/차트 캡션 위치
- Base/단위 표기
- 결과표 행/열/헤더
- 배너 그룹 행
- 표 선/폰트/정렬
- 페이지 넘김
- 원본 템플릿 불변

## 8. 당장 다음 작업

다음 개발 단위는 다음 순서가 적절하다.

1. `hwp_template_probe.py`를 개선해 셀 병합/스타일 정보를 추출한다.
2. `template_blueprint.py`를 추가해 결과표 반복 블록 후보를 만든다.
3. 제공 템플릿 중 국립암센터 HWPX를 기준으로 `RESULT_BLOCK_001` blueprint를 수동/자동 혼합으로 만든다.
4. Excel 없이 fake `report_package_v2` 하나를 만들어 실제 HWPX 한 페이지를 생성한다.
5. 그 결과를 사용자가 열어보고 “표 위치/크기/서식이 맞는지” 확인한다.

이후 Excel 산출물 연결은 그다음이다. 현재 상태에서 Excel을 먼저 연결하면 표 구조가 단순화되어 다시 개발 방향이 틀어질 가능성이 크다.
